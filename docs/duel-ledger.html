Duels · the target

How a duel works

Every gate serves this sequence. Steps marked by the server are the ones a player's browser must not be able to fake.

  1. Challenge or queue

    A member challenges someone from the lobby, or joins quick match for a format. Invites expire after 15 minutes; the queue pairs by rating and widens the band the longer you wait.

  2. Accept, and the problem is already there

    Accepting picks a problem from the reviewed bank by both players' rating and topics neither has seen against the other. No AI call happens while someone waits.

  3. Start on the server clock

    The server stamps started_at and every deadline. Clients show a countdown; they never decide when time is up.

  4. Play

    Run checks the public samples in the browser (Pyodide), as today. Each Submit is recorded server-side with code and time.

  5. Judge on the server

    A judge function re-runs the submitted code against the hidden tests, which never leave the server. Its verdict is the one that counts.

  6. Finish once

    One server function settles the match: winner, reason (solved, time, forfeit), Elo for both players, XP and streaks, in one transaction. Disconnecting for 60 seconds forfeits.

  7. Show and share

    Both players and spectators see the same result. History, replays, the ladder and the feed read the settled record.

Duels · audit 1 Oct 2026

Where duels stand today

Read from the code and migrations on main. These are the reasons the gates are ordered the way they are.

  • Integrity
    Players write their own rating.

    Migration 20260611120000 lets each player update their own duel_profiles row, and applyOwnRatingUpdate does exactly that from the browser. Anyone can set any rating, wins or XP from the console.

  • Integrity
    The result is whatever a client says.

    Both clients race finishMatchRecord and broadcast a finish event; the first conditional write wins. Nothing checks that the winner's code actually passed.

  • Integrity
    Hidden tests are readable.

    duel_problems.test_cases_json holds hidden cases alongside public ones, and any signed-in member can select active problems.

  • Reliability
    The problem is generated while the accepter waits.

    acceptInviteAndCreateMatch calls generateDuelQuizSet at accept time. Slow or failed AI falls back to the built-in bank, but the wait is long and quality varies.

  • Reliability
    No expiry, no forfeit, no resume.

    Invites never become EXPIRED; a forfeit reason exists but nothing triggers it; the countdown is the client's own tick(), so a refresh or a closed laptop leaves a match hanging.

  • Unused
    Five tables are built and never read.

    duel_matchmaking_queue, duel_tournaments, duel_seasons, duel_user_badges and duel_anti_cheat_events exist from 20260524143000; no service touches them. Anti-cheat signals stay in the browser.

Keep

Already ahead — don't rebuild

  • Deterministic judging in the browser. duelRunner.ts runs solve() per case in Pyodide with fresh namespaces. It stays as the Run check and becomes the reference for the server judge.
  • Expected outputs come from a reference solution. buildCodingCard runs the reference to derive outputs, so an AI's wrong answer key cannot fail a correct player.
  • Live spectating. Spectator view, presence counts and match chat with taunts already stream over realtime channels.
  • A working fallback bank. duelProblemBank.ts and duelQuizBank.ts keep duels playable when AI is down — the seed for Gate 2's reviewed bank.
  • The lobby is on the Split shell. Live, For you, Waiting and Ladder views on real invites and matches, with a record panel (this release).

Decided

Deliberately not building

  • Wagering points, badges or XP. Betting on outcomes turns practice into a stake. Ratings move; nothing is staked.
  • Voice or video in matches. Text chat and taunts are enough at a desk in a computer lab; a media stack is a large build for little return.
  • Open matchmaking with other schools. Duels stay inside the club, where patrons can moderate. Revisit only for an organised inter-school event (Gate 9).
  • Raw speed ladders for beginners. Beginner duels rank by tests passed first and time second, so typing speed doesn't decide a learner's match.
  • AI-written opponents. Practice races a real recorded timeline (Gate 3) rather than a bot, so the bar is a classmate's actual pace.
